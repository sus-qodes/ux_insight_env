Documentation

Complete reference for the UX Insight Analyst reinforcement learning environment.

Overview

The UX Insight Analyst environment simulates the work of a UX analyst reviewing e-commerce behavioral analytics data. The agent receives synthetic but realistic analytics from the StyleMart platform and must produce structured, actionable UI/UX findings.

Built on the OpenEnv framework. Implements the standard three-method interface: reset(), step(action), and state.

Quick Start

Python Client

from client import UXInsightEnv
from models import UXAction

env = UXInsightEnv(base_url="https://sushere-ux-insight-env.hf.space")
await env.connect()

result = await env.reset(task_id="easy", seed=101)
obs = result.observation

action = UXAction(
    finding_type="issue",
    affected_element="Flash Sale banner image",
    issue_category="dead_click",
    severity="high",
    recommendation="Make the Flash Sale banner image clickable...",
    fix_category="fix_broken_link",
    impact_estimate="Expected 20-30% reduction in dead clicks.",
    confidence=0.9,
)

result = await env.step(action)
print(f"Reward: {result.reward}, Done: {result.done}")

GET /health

Returns server status. No parameters.

{"status": "healthy"}

POST /reset

Start a new episode. Returns the initial observation.

ParameterTypeRequiredDescription
seedintNoRandom seed for deterministic generation
episode_idstrNoTask selector: "easy", "medium", or "hard"
task_idstrNoAlias for episode_id

Response: {"observation": UXObservation, "reward": null, "done": false}

POST /step

Submit an action for the current page. Returns observation with reward and done flag.

ParameterTypeRequiredDescription
actionUXActionYesThe structured finding (see UXAction schema)

Response: {"observation": UXObservation, "reward": float, "done": bool}

GET /state

Returns internal environment state. Hidden from agent during evaluation; useful for debugging.

Response: UXState object.

GET /web

OpenEnv Playground web interface. Interactive form for submitting actions and viewing results.

Tasks

Easy (1 step)

One page with a single clear, high-signal problem (rage click or dead click). The agent must identify the issue, categorize it, assess severity, and recommend a fix. Basic LLMs should solve this reliably.

Medium (3 steps)

Three pages with different severity levels. The agent must analyze each page independently and demonstrate correct severity ranking across the episode. Requires multi-step reasoning and prioritization.

Hard (6 steps)

Six pages including real issues, red herrings (normal behaviors that look anomalous), and clean pages. The agent must resist false positives, handle conflicting signals, and provide impact-estimated recommendations. Requires careful analytical reasoning.

Grading System

Each step is graded against embedded ground truth. The grade is a float in [0.0, 1.0].

Case 1: Page has real problem(s)

The grader finds the best-matching ground-truth problem and scores across five dimensions:

DimensionWeightMethod
Element identification25%Keyword overlap (Jaccard) between agent element and ground truth
Issue category20%Exact match = 1.0, related category = 0.5, else 0.0
Severity15%Exact = 1.0, off-by-one = 0.5, else 0.0
Recommendation25%Keyword coverage against expected keywords + element mention + length check
Fix category15%Exact match = full, compatible pair = half

Case 2: Page has no real problems (clean or red herring only)

Agent ResponseScore
no_issue + normal_behavior + severity: noneUp to 1.0
ambiguous0.20 (partial credit for uncertainty)
issue (false positive)-0.10 penalty

Reward Function

The step reward wraps the grade with additional adjustments. Base reward equals the step grade. Penalties are subtracted. Final reward is clamped to [-0.5, 1.0].

Penalties

ConditionPenalty
Duplicate finding (same element + category as prior step)-0.40
Inconsistent: finding_type="issue" with severity="none"-0.20
Overconfident wrong: grade < 0.3 and confidence > 0.8-0.10
Trivial recommendation: under 10 characters-0.15
Invalid issue_category or fix_category-0.20
no_issue finding with severity not "none"Action rejected
issue finding with fix_category "no_fix_needed"Action rejected

Episode Bonuses

Applied after the final step. Range: [-0.10, +0.25].

BonusApplies ToRange
Priority ordering (severity ranking across findings)medium, hard0.00 to +0.10
Red herring handling (correct no_issue on trap pages)hard only0.00 to +0.10
Impact estimate quality (specificity of metric predictions)hard only0.00 to +0.05
False positive penaltyall-0.05 per FP

Red Herrings

The hard task includes red-herring pages: data that looks anomalous but is actually normal. The agent must correctly identify these as no_issue.

ExampleWhy It Is Normal
89% exit rate on order confirmation pagePurchase is complete; users naturally leave
76% "bounce" rate on login pageSuccessful logins redirect away (analytics records as bounce)
Deep scroll + 3min on product detail pageUsers are reading reviews thoroughly -- engagement, not friction
15% quickback from wishlistWithin normal range; users briefly check and navigate to a product

Docker

# Build
docker build -t ux-insight-env:latest -f server/Dockerfile .

# Run
docker run --rm -p 7860:7860 ux-insight-env:latest

# Verify
curl http://localhost:7860/health

Base image: python:3.11-slim. Single worker. Port 7860. Fits within 2 vCPU / 8 GB RAM.

Inference Script

The baseline script runs all tasks against the HF inference API.

# Single model (default)
export HF_TOKEN="hf_..."
export MODEL_NAME="meta-llama/Llama-3.3-70B-Instruct"
python inference.py

# All baseline models
export RUN_ALL_BASELINES=true
python inference.py

OPENENV_BASE_URLhttps://sushere-ux-insight-env.hf.spaceEnvironment endpoint
RUN_ALL_BASELINESfalseSet to "true" to run all 5 models
